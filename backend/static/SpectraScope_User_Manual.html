Build a three-date HLS bundle

Search NASA HLS and prepare six reflectance bands per date for Prithvi Crop/LULC.

  1. Search HLS L30 or HLS S30 for your area and dates. Use NASA Earthdata Login to download the science files. You can request several dates in one Earthdata batch.
  2. Import the folder. The catalog identifies each HLS tile and date, preserves its science bands and lists quality and angle files separately.
  3. In Local imagery, select three distinct dates from the same HLS tile and choose Build 3-date HLS bundle. The app verifies the common 30 m grid and chooses blue, green, red, near infrared and both shortwave infrared bands from each date.
  4. Add the bundle to a mission and choose Prithvi Crop/LULC in Manual inference. The original acquisitions remain in the catalog.

CBERS-4A WPM Level 4 is searchable through INPE. For Maxar WorldView or GeoEye imagery from the Maxar event archive, download from the provider and import locally. Select Maxar in the band inspector if the source metadata does not identify it.

The three mission workspaces

Automatic pipelines, Training & qualification, and Manual inference.

Open a mission and choose one of its three workspaces. The catalog, source data, review desk, layers and Insights support these workspaces.

  1. Automatic pipelines: choose an AOI, sensors and a local or online catalog. Connect installed algorithms and export blocks in the diagram. Validate and save the diagram, then activate monitoring explicitly. The pipeline discovers intersecting images and tracks each execution.
  2. Training & qualification: define the classes for a locally trainable model. Label or import reference data, assigning independent validation regions separately. Check sample coverage, train a candidate, and review Precision, Recall and F1 against your goals. Sample counts are guidance, not measured accuracy. Confirm your review, add a release note and use the qualification action to make the version available in Manual inference and pipelines. Returning it to Training blocks its operational use.
  3. Manual inference: select images and one or more compatible models. Native pretrained models are available directly, without local training. SAM requires source-image prompts. Review results explicitly and choose the export format.

Pause, Resume and Stop act at safe processing checkpoints; they may wait for the current native operation. Stop preserves existing inputs and artifacts. Deletion archives operational records rather than erasing scientific evidence. Use the mission logs to inspect errors and download diagnostics.

Object detectors require suitable image resolution; Sentinel/Landsat cannot resolve ordinary small vehicles reliably. Published benchmark results are not local accuracy. Open Data & results → Services & workers for private source connections, coordinate conversions, algorithm inspection and worker settings.

Find or connect a read-only source

Search approved folders and saved sources, or prepare an inspection or connection.

Open Services & workers, then Describe a discovery request. Enter find catalog archive or find triangulation camera, then choose Find or prepare. The search checks saved configurations and files directly inside approved folders. It uses filenames, not file contents. Approve the specific folder if the file is in a subfolder.

With local Ollama configured, select Use local chat to interpret the request to ask in ordinary language. The local model chooses a search type and optional name. It cannot contact suppliers, connect to results or scan the network.

If you know the source, enter inspect catalog /data/catalog.sqlite, connect ogc_features https://internal-host/features, or connect mcp 10.0.0.2:9443/mcp. The form opens for review. Add credentials only in the connection form. For OGC Features, map the local raster-path property and optionally the top-level identifier and geometry. Select rows, review the import plan and approve indexing.

For MCP, choose a listed GeoJSON imagery resource in API connections and read it. Map the image path and optional ID and footprint, then review the import plan. The app uses the saved snapshot for preview and indexing, and opens selected local raster paths only inside approved source roots.

An OpenAPI inventory can suggest an existing STAC or OGC connector. Preparing it fills a draft. Review the endpoint and choose Connect read-only to run the verified connector checks. Documented operations and server URLs are never used to connect automatically.

For ArcGIS Enterprise 11.x, select ArcGIS Enterprise FeatureServer layer and enter the full internal HTTPS URL ending in /FeatureServer/0 (replace 0 with the layer ID). Use a Query-only layer with pagination and GeoJSON support. Map the local image-path field and optionally native geometry. Enter an exact numeric object ID to look up one feature. For area search, leave the ID blank and enter a WGS84 rectangle or copy the map bounds. Area search verifies point and polygon footprints. For a layer that declares one UTC time field, reconnect to enable an inclusive UTC date filter. Layer time is recorded separately from any mapped image acquisition time. After preview, select and approve only the rows you want to index.

For a private STAC catalog backed by a local mount, map properties.local_path or an explicit assets.<key>.href. Use a path to a product folder or a complete multiband raster. Relative paths require an approved local root. Remote asset URLs stay unavailable for this import. Review and approve the selected local rows. To group separate single-band files as one product, enter a mapping such as RED=assets.red.href, GREEN=assets.green.href and supply the approved local root. Preview requires all chosen science assets. A bundle can contain up to 128 explicitly mapped single-band assets. Paste comma-separated mappings across multiple lines. For large bundles, use an exact item or a narrow collection preview. Enter an exact STAC item ID to retrieve a known item directly, or leave it blank for a collection preview. For OGC API Features or Records, enter an exact feature or record ID, or leave it blank and filter a collection by area. Area filtering checks returned point and polygon footprints. OGC Records also supports an inclusive UTC date window on the record time. This filter keeps the record time separate from any mapped image acquisition timestamp. For a date-filtered preview, leave the item ID blank and enter both UTC dates. The preview includes both dates and reads only one bounded page. To filter by location, enter a non-wrapping WGS84 rectangle or copy the bounds of a map polygon or rectangle. Preview sends those bounds to your selected private catalog. The rectangle can be combined with the UTC dates. Use Find asset keys to see keys for band mapping. This list contains item IDs and keys only. It follows the exact item ID or the area and UTC date filters entered above. Declared scale, offset and nodata are checked before indexing. Declared asset center wavelengths are converted from micrometres to nanometres. Conflicts with the raster header require review. Declared bandwidth is retained in catalog provenance. For a multiband raster in one asset, map its asset path. Declared channel names and wavelengths are kept in file order. A STAC scale and offset can calibrate a channel whose raster header uses the default scale 1 and offset 0. Conflicting non-default raster calibration or nodata blocks approval.

Qualify a portable land-cover model

Inspect and qualify a fixed, data-only model for manual and automatic inference.

  1. Open a mission with a validation job and connected source imagery. In Data & results → Services & workers → Algorithm onboarding, inspect the package inventory with Land cover selected.
  2. Verify the file checksums and choose Prepare portable LULC for validation. Confirm usage rights and that the imagery and labels were held out of supplier fitting and tuning. Select the job and set the minimum precision, recall, F1 and validation pixel count.
  3. In Training & qualification, add human validation references for every class, each assigned to its source image. Choose Run independent validation. Review the results and explicitly release the model if it meets the goals.
  4. Use the qualified model in Manual inference or an Automatic pipelines algorithm block. Use Revalidate to return it to qualification and block operational use while retaining existing outputs.

Supported package format

The inventory schema is geo-intelligence-algorithm-inventory-v1. Use task lulc and list one model JSON file with role config and a license file with role license. The JSON example below illustrates the schema. Its numbers are examples only.

{"schema":"geo-intelligence-linear-lulc-v1","classes":["Water","Trees"],"sensors":["sentinel-2"],"processing_levels":["L2A"],"bands":["RED"],"ranges":[[0,1]],"coefficients":[[-10],[10]],"intercepts":[4.5,-4.5]}

Each coefficient row and intercept correspond to one class in the declared order. Band names match the raster engine’s mapped names. Ranges use the engine’s scaled values. Use UNSPECIFIED only for intentionally untagged products. The softmax scores are uncalibrated. The CPU runtime scores fixed coefficients per valid pixel. Supplier scripts can be inspected as text but never run. Other model formats need their own reviewed adapters.

Validate a world file

Verify a supplier affine transform with independent control points.

In Image ↔ ground, enter the absolute world-file path, open Validate a geolocation sidecar, and supply the image dimensions, EPSG code and at least four independent control points spread across the image. Use continuous column and row coordinates from the upper-left corner for the check points. The service accounts for the world file’s pixel-centre convention.

Review the residual and approve the candidate to enable conversion. The saved recipe is bound to the source file checksum.

Validate an RPC sidecar

Approve an RPB or GDAL/GeoEye RPC text file using independent 3D control points.

Convert pixel detections

Open a geolocation configuration and choose Convert pixel detections. Supply a Shapefile with its .shx and .dbf files, or a .geojson FeatureCollection containing two-dimensional image column,row coordinates and no declared CRS. Confirm the file belongs to the selected image. Use the selected model and enter ellipsoidal height when required. The app converts vertices and saves a new geographic GeoJSON in the private workspace. Choose Download GeoJSON after conversion. Use Browse saved vectors to find and download older results.

Validate embedded geolocation

Inspect a GeoTIFF or JP2. If an affine, GCP or RPC model is found, open Validate embedded geolocation, enter at least four independent checkpoints, and approve the version after the residuals pass. RPC checkpoints also require ellipsoidal height in metres. GCP checkpoints must be distinct from the fitting points. This GCP conversion is planar and uses no height. For GCPs in a GDAL .aux.xml sidecar, use Validate a geolocation sidecar and enter the image dimensions. A supported sidecar contains one dataset-level GCP list with an offline EPSG coordinate system.

In Services & workers → Image ↔ ground, enter the absolute path to an RPC00B .rpb file under an approved source folder. Open Validate a geolocation sidecar and give the original image width and height.

Provide four or more independent checkpoints distributed across the image. Use continuous column and row from the upper-left corner, WGS84 longitude and latitude, and the point’s ellipsoidal height in metres. Each JSON entry has the form {"pixel":[120.5,85.5],"ground":[34.81,32.07],"height_metres":53.0}. Enter the maximum allowed error in pixels. These example numbers illustrate the fields.

Choose Validate sidecar, review the measured residual for the supplied checkpoints, then approve the candidate. For conversion, enter an explicit ellipsoidal height. Revalidate if the sidecar changes. Results depend on the height and the quality of the supplier model and check points.

GDAL/GeoEye numbered text sidecars use .rpc or _RPC.TXT and the same control-point and approval workflow. Unknown coefficient layouts require a reviewed parser.

For a JSON or XML affine example, open Register a JSON or XML affine format, enter independent control points and choose Suggest & validate mapping. The agent looks for one recognizable group of transform, EPSG code and image dimensions. Review the validated field mapping and approve when it matches the sample. If more than one mapping is possible, enter the paths explicitly. For XML, include the root element in each literal dotted path, such as Vendor.Header.GeoTransform. Use one text element per value and a declared EPSG code. Select the coefficient order when you enter a mapping manually. XML links and attributes are ignored.

For a full-scene Pléiades, Pléiades Neo, SPOT 6 or SPOT 7 DIMAP RPC product, supply the RPC_*.XML sidecar and dimensions of the entire scene. Validate with full-scene pixel coordinates. For a non-overlapping regular tile, expand DIMAP tile coordinates and provide the matching DIM_*.XML and tile filename. Enter the actual tile dimensions, including a smaller edge tile, and supply tile-local control points. Both metadata files are checked again at approval and conversion.

Train one U-Net on enrolled workers

Use two to four private CPU or GPU workers with checkpoint recovery.

In Services & workers → Worker pool, enroll approved workers, turn on routing, and choose two to four workers under U-Net training. Remote workers connect over internal HTTPS with a verified certificate. Each worker needs a 5 GiB RAM budget. Compatible CUDA or MPS devices with at least 4 GiB available in the enrollment budget are preferred, with CPU workers eligible.

In Training & qualification, choose a U-Net configuration with reviewed labels and separate validation references. Select up to eight source images and a grid of 384 pixels or less. Each round combines the fitting gradients from every assigned worker before it saves the candidate checkpoint. Validation references and their pixel values are excluded from worker fitting inputs. Validation runs on the coordinator.

Pause and stop use safe checkpoints. During a restart, the coordinator checks the last completed barrier and reuses verified gradient contributions. Restart an assigned worker under its existing enrollment to resume that partition. Review Precision, Recall and F1 before releasing the candidate. Training alone does not release it.

Improve a rotated object detector

Compare a new few-shot candidate against a baseline on independent images.

  1. In Manual inference, open Detection experiments. Use Open rotated box labeling to save human-reviewed training boxes for each object class. Use 3–10 distinct examples per class.
  2. On a different acquisition, label the same classes as Validation. Select that image and choose Build & compare candidate. The app saves the candidate and compares nearest examples with a class-centroid baseline on the same rotated boxes.
  3. In Progress & results, choose Evaluate against validation boxes. For a complete image annotation, confirm you marked all target objects. The review reports per-class precision, recall, F1 and AP50 and shows whether precision reaches 80%. Partial annotation supports miss diagnosis.
  4. Use the report to decide whether to improve box proposals, add examples for confused classes, or review duplicates. Use Evaluate saved candidate on another independently labeled acquisition to test the same weights without fitting again.

The proposal detector limits which objects can be found. The reviewed example is not an operational release. Experiments use local source pixels and local model packs, and retain their GeoJSON and evidence.

Enhance native Sentinel-2 bands with DSen2

Export model-enhanced 20 m or 60 m science bands on the native 10 m guide grid.

Import a local Sentinel-2 L1C SAFE product with its original calibration XML and native grids. In Manual inference, choose the DSen2 20 m or 60 m model. The 60 m model also needs the 20 m bands. Run over the job area and download the continuous GeoTIFF from Progress & results.

In Automatic pipelines, select Super-resolution with a local catalog and connect DSen2 to a GeoTIFF export block. The result preserves original band resolution in its report. Connect a private catalog

Discover read-only image catalogs, map their fields and approve local imagery imports.

Open Data & results → Services & workers → Catalog connections and connect using the local workspace access key. Choose a supported engine, enter the internal endpoint and use an existing read-only account. MySQL 8.4 requires verified TLS, including on the same computer. SQL Server 2022, SQL Server 2025 and Oracle AI Database 26ai (23.26.2 or newer within 26ai) require an approved PEM CA file and the offline catalog connector component 1.2.0. SQL Server requires a dedicated SQL login with direct SELECT grants and database VIEW DEFINITION. Choose the entry matching the server version. SQL Server 2025 rechecks the recorded build before each preview. Oracle requires CREATE SESSION and direct READ grants. Oracle connects to the TCPS listener. PostgreSQL with PostGIS 3.5 can map native 2D EPSG:4326 geometry. Approved imports retain it as supplier provenance and derive the operational footprint from the raster.

  1. Read the available tables or collections. Map the path and any image identifier, date or other metadata fields.
  2. Read a preview and tick the images to inspect. If supplier paths differ from the paths visible here, map the supplier prefix to an approved local folder.
  3. Review the products and approve the import. Open Local imagery to use them. This does not enable folder monitoring.

For an unlisted engine, use an existing read-only STAC endpoint for metadata discovery or inspect an existing UTF-8 CSV export with accessible image paths. Use My database engine isn’t listed to save product and version details locally. A pending record does not establish a live connection. Supplier systems are read-only; credentials and learned mappings stay inside the workspace.

For an existing GeoJSON FeatureCollection, enter the absolute .geojson path in the catalog inspector. Map the property that holds the local image path. Optional fields @id and @geometry read the feature identifier and two-dimensional CRS84 footprint. Preview the rows, choose the images, and approve the import. If the export changes before approval, inspect it again.

SAM 3 interactive segmentation

Local point/box proposals with no account or web API.

SAM 3 Tracker replaces the active SAM 2.1 adapter. It uses a publicly downloadable ONNX Community conversion with a quantized vision encoder and a full-precision mask decoder. No account, online API or runtime model download is used.

On Windows, install the separate S3/3.exe component with its adjacent payload folder, then the small application update. This preserves the stable base prerequisites. Point and box prompts work on a mapped three-band display composite. Text-concept prompting is not included in this adapter.

The worker uses a supported dedicated CUDA GPU when available in the runtime, otherwise CPU. CPU inference needs substantial working memory—about 8 GiB free is recommended. A free-memory check reports insufficient RAM instead of substituting another model.

Proposals remain unclassified, and model quality scores are not measured accuracy. Assign a class and explicitly save your decision to create a reference. SAM fine-tuning remains unsupported. Historical SAM 2 tasks and outputs retain their original model identity and cannot be resumed with SAM 3 weights.

Landsat calibration metadata

Import the supplier MTL with Landsat 8/9 Collection-2 Level-2 bands.

Keep the original *_MTL.txt, XML or JSON beside the Landsat band folders. The importer reads the declared Level-2 coefficients, rather than the different Level-1 coefficients stored elsewhere in the same MTL.

Surface reflectance bands retain their individual scale/offset. ST_B10 is retained as temperature in kelvin. Thermal auxiliary, quality, mask and preview files do not become separate catalog images.

For a previously saved uncalibrated Landsat source, open Source data and use Attach Landsat MTL. The metadata must match every saved band. This creates a new input recipe; earlier runs and original band pixels remain unchanged. Start a new analysis to use the repaired recipe.

Dynamic World requires Sentinel L1C. Prithvi Crop needs a genuine three-date HLS stack. OpenEarthMap needs 0.25–0.5 m RGB; it cannot use ordinary Sentinel/Landsat pixels.

Compare an image with its result

Swipe, zoom, opacity, pixel inspection and rectangular corrections without a geographic map.

In a mission, open Runs & results, then Open image & classification or Open image & agreement. The large image desk places the saved source RGB beneath the result; it does not add either layer to the map.

  1. Drag the white divider or use the Swipe slider. Only the dividing line moves.
  2. Scroll or use +/− to zoom. Drag the image to pan. Both layers move together. Fit image resets the view; Expand fills the screen.
  3. Change Result opacity to see through the overlay. These are display settings; scientific raster values do not change.
  4. Click the image to inspect saved model votes. For a correction choose Use clicked pixel, or Draw image region and drag a rectangle. Choose a class and reference role, then save.

RGB is a bounded display preview with a percentile stretch; pixel inspection and saved corrections use the georeferenced analysis grid. The original science bands and model outputs are preserved.

To delete a mission without opening it, use Delete mission on its mission-list card. Confirmation explains that active runs are stopped and saved imagery, results and corrections are retained.

The catalog lists logical image products, not standalone thumbnails, quality files or masks. Mission and result views keep the supplier/product name shown in the catalog; internal IDs are used only for database relationships.

Import bands and supplier calibration

Keep each acquisition and its calibration metadata together.

A multiband image can be one file or several band files. Use Import folder to keep the supplier's directory structure and filenames. Bands from one acquisition are grouped as one product; different acquisitions remain separate. Inspect the detected bands before adding them to a job.

Sentinel SAFE: include MTD_MSIL1C.xml or MTD_MSIL2A.xml. The application reads the declared quantification value and per-band offsets and saves the metadata with the job's band snapshots. Source pixels remain unchanged. DN zero stays nodata; negative calibrated reflectance is retained.

If an older import omitted its XML, open Source data and choose Attach SAFE metadata on the matching image. The product identity is checked. This creates a new input version and preserves earlier runs. Run the analysis again to produce new outputs.

Landsat grouping: retain matching names such as LC08_…_SR_B1.TIF through the other bands of that same acquisition, plus its MTL file. Band folders may be siblings under one selected parent. A grouped product is not, by itself, proof of correct radiometric calibration. MTL files are retained; the SAFE XML attachment tool is specifically for Sentinel products.

Mission workflow and image review

Choose images, configure source data, run analysis, and review results over the original image.

  1. Manual inference: choose a job, images and a compatible released model. Source thumbnails appear when available.
  2. Source data: connect the actual bands using saved local files, streaming or download. The mission guide shows how many images are ready.
  3. Runs & results: follow processing progress and open a completed result.
  4. Review on image: see the classification above a stretched RGB display of its saved source image. Use the image viewer’s opacity and swipe controls. Inspect pixels and save explicit corrections.

Pause waits for a safe checkpoint. Resume continues a paused worker. Stop preserves completed artifacts and cancels unfinished work at its next checkpoint. Resuming a stopped mission enables new runs; it does not restart cancelled runs. Remove mission stops active work and hides the mission while preserving its data locally.

Dynamic World inference on Sentinel-2 L1C automatically processes the full chosen AOI in bounded windows at 10 m. The grid selector controls block size for this model, not final resolution. Coarser science bands are resampled to that grid; original bands are preserved. A 10 m output does not add native detail to a coarser band. Thumbnails and opacity are display features and never alter analytical rasters.

Offline desktop installation

Install and use the self-contained Windows or Mac desktop edition.

Install from prepared media

The desktop application includes its own window, browser engine, Python, local model runtime, pretrained weights, map scripts and fonts. No separate Docker, Python, browser or Ollama installation is required.

  1. Windows x64: copy the complete SS-0225 folder and keep each payload beside its wizard. For a new Current User installation run 1.exe, then 2.exe, then the detector wizards D1/4.exe and D2/5.exe if you want Detection experiments. Use the same installation directory throughout. On an existing compatible installation, stop the app and run 2.exe for a code-only update. Install any missing detector packs separately. The wizards use your Windows user profile and app-local Microsoft DLLs. The older machine-wide updater is separate.
  2. Mac Apple Silicon, macOS 14 or later: use a verified matching Mac installer when one is available. The existing installation folder and workspace name remain SpectraScope.
  3. Windows: choose your workspace and LLM preference in the installation/update wizard. It verifies files and checks native libraries before Finish. Later launches start services only. The older Mac installer may request these settings on first launch. Interrupted application setup offers Resume setup; rerun an interrupted Windows update to recover and resume verification. Only an algorithm you actually run prepares its writable model cache.

Profiles and storage

Automatic selection uses Qwen3.5 2B on a 16 GB machine and 4B on machines with at least 24 GB. The 9B option is intended for 48 GB or more. All three model packs are supplied; switching among them requires no download. Compatible dedicated GPUs are used when supported; otherwise analysis uses CPU. On Apple Silicon, supported native inference can use MPS. Incompatible devices use CPU. A Windows NVIDIA GPU needs a compatible driver already installed.

Bring your imagery

Choose Import local imagery to copy a georeferenced GeoTIFF or JPEG2000 into your workspace and select it for a mission. Local imports can be selected for new jobs. Ready monitored products populate the Local imagery table automatically, including while the monitoring dialog is closed. In Data & results → Source data, verify band names, product type, reflectance units and temporal dates before running a compatible model. The import date is recorded as an import time, not a claimed satellite acquisition date. Recognized products and explicit band manifests can supply acquisition dates; unknown acquisition times remain labeled as import times.

Automatic online maps and catalogs

After installation completes, Geo Intelligence checks the built-in street-map, Esri satellite/aerial and satellite-catalog services. When connected, select Sentinel-2 or Landsat normally; the existing map providers are available without entering a URL. The top bar shows connection status and application version. If services become unreachable, the map uses the bundled world map. Your chosen catalog tab, results and selections stay in place. Online search pauses; Local imagery remains available in its own tab. Reachable services reconnect automatically without switching your tab. Checks run about every 30 seconds. A firewall, proxy, sign-in page or provider outage can leave individual services unavailable even when the computer has a network connection.

Installation/native validation and model packs stay local. Online mode uses the installed model packs and an approved internal model service. For explicit offline-only use, stop local services and launch with --offline; restart without that flag to restore automatic connectivity.

Draw & use an AOI

Rectangles, complex polygons, coordinate points and the area used by a job.

Rectangle or polygon

  1. Use the drawing controls inside the map. Choose rectangle for a box or polygon for a custom outline.
  2. Place the vertices and finish the geometry using the map tool's completion gesture. While tracing a complex boundary, keep adding vertices; the final outline should be an unambiguous, well-defined polygon.
  3. Choose Use drawn area to read the latest completed drawing. Confirm that the AOI status describes the intended shape before searching.

Point coordinates

Enter Longitude first (−180 to 180), then Latitude (−90 to 90), in WGS84 decimal degrees. For example, longitude 35.21, latitude 31.77. Choose Place point AOI. Do not enter projected easting/northing values in these fields.

A point is not a processing polygon

It can locate catalog scenes. Draw a polygon or rectangle when you want an explicit processing boundary; the raster reader does not crop a point to an invented user-specified radius.

Drawings, footprints and review regions

The AOI is your chosen search or reference geometry. Catalog footprints show the acquisition extent of scenes. A review region is the pixel or drawing you explicitly approve as a reference. They serve different purposes even when displayed together.

A new job stores the current AOI with the selected imagery. Redrawing a search area later does not silently redefine an existing job. Before starting analysis, check the job's area and imagery. A shape outside a raster's coverage cannot provide valid analysis pixels.

If a drawing was not picked up, finish it, leave drawing mode if necessary, choose Use drawn area again and confirm the status. Avoid leaving a self-intersecting or unfinished final boundary.

Local folders and multiband products

Group band files into images and control folder monitoring with saved checkboxes.

Import one logical image with its bands

Choose Import local imagery to select all source files, or Import multiband folder to select a complete directory tree. A multiband raster stays one image. Recognized scene-and-band filenames and sibling band folders are grouped into one image product. Separate acquisitions are kept separate. A browser cannot access sibling files you did not select; select the entire product folder when its bands are separate.

The monitoring checkbox is the switch

Use the prominent Folder monitoring panel on the main workspace, then choose Manage folders & image library. Add an absolute local folder path on the computer running the app. Monitor this folder is saved exactly as checked or unchecked: checked starts continuous polling while local services run and resumes after restart; unchecked pauses monitoring. There is no automatic profile or hardware rule that overrides your checkbox. In the browser edition, local services remain in the notification area when the browser tab closes. When services are stopped, monitoring stops and catches up after restart if the checkbox is checked.

Checks normally run every 30 seconds; the confirmation scan for a changed folder runs after about two seconds. Scan now checks an enabled folder immediately. The index waits for file writes to settle and for the folder contents to remain stable across two scans. Large transfers can take longer. Last scan, file and product counts, scan status, errors and required reviews are visible beside each folder. A bad file no longer blocks unrelated valid acquisitions. An unreadable band holds its whole acquisition for review rather than silently dropping that band. Use Browse all ready images to show cataloged products without the AOI or date filters; an older acquisition can otherwise be excluded by your search dates. An unavailable folder retains its last catalog and reports an error; removing files from an available folder updates the active catalog after a stable scan. Removing a monitoring entry does not delete files or saved job inputs.

Inspect the grouping before analysis

Each library row shows its source-file count, channel count and expected-band completeness. Choose Inspect bands to see every selected file, native grid and channel names. Bare filenames, repeated bands, incomplete known products and conflicting footprints require explicit review. Select files, name every channel and confirm that they form one acquisition. Invalid or non-overlapping groups cannot be approved. If an expected band count is not declared, completeness is not asserted.

For Sentinel-2, alternative resolutions of a band are retained as alternatives and the finest matching grid is selected. Known quality, display and atmospheric retrieval files are listed as non-spectral exclusions. Science channels are never silently reduced. Native scales, offsets and nodata masks are preserved; verify units and product type before pretrained inference. Automatic grouping is not evidence that radiometric calibration or sensor compatibility has been verified. Declared scene/acquisition metadata can identify an image across otherwise unrelated filenames. Declared wavelength units are retained or explicitly converted to nm; missing units are not guessed.

Custom hyperspectral layouts

For other filenames, add spectrascope-image.json beside the band folders. Declare a product name, acquisition datetime, sensor and a bands list. Each entry has a relative path and name; optionally supply wavelength_nm, scale and offset. A multiband file is declared once with band_names in its actual channel order. A temporal Prithvi HLS product declares processing_level: HLS and three distinct actual temporal_dates, with the six HLS bands in date order. Repeated spectral names are allowed only for that declared temporal schema. expected_bands declares completeness. See the example in the library dialog. Paths cannot escape the imported folder or point to URLs.

Saved inputs and storage

Monitoring indexes files in place. Adding a product to a mission/job preserves immutable application-managed copies of every selected source band, with checksums, original paths, names and metadata. Changed files create catalog revisions; existing jobs retain their original snapshots. Copies use disk space only for selected content, with equal-content reuse. The shared reader aligns different native grids spatially and records resampling; the original bands remain intact. Changed or damaged source snapshots stop inference with an error.

Formats and deployments

Supported local science formats are georeferenced GeoTIFF and JPEG2000, not arbitrary ENVI/HDF/NetCDF products. Convert unsupported products with their georeferencing and band metadata preserved before importing. Manual uploads allow 5 GB per raster; local monitoring supports larger files. Processing grids have a memory budget and reject oversized full-band cubes rather than dropping spectral channels. In Docker, set SPECTRASCOPE_IMAGERY_DIR to a host parent directory before starting the stack; its read-only container path is /app/imports. Enter that container path, not an unmounted host path, in the library. Offline native editions accept local drives, not remote URLs, network shares or VRT inputs.

Prepare imagery

Bands, products & analysis grid

Preserve spectral meaning and choose compatible inputs and spatial resolution.

Map band names to actual channels

Enter comma-separated names in Band names · optional when the stack lacks trustworthy band descriptions. The number of names must match the raster's channels. For a six-band reflectance stack an example is BLUE,GREEN,RED,NIR,SWIR1,SWIR2. Never use this list for a differently ordered raster without checking its metadata.

Sentinel-2 maps B2/B3/B4 to BLUE/GREEN/RED, B8A to narrow NIR, and B11/B12 to SWIR1/SWIR2. B8 and B8A are distinct inputs. Dynamic World additionally uses B5, B6, B7 and B8. Landsat band numbering differs; the adapter uses its catalog metadata to interpret common names.

Product type matters

L1C is top-of-atmosphere reflectance; L2A is surface reflectance. They are not interchangeable for a pretrained model. HLS temporal models need three genuine acquisition dates and the required 18-channel layout. RGB for OpenEarthMap means very-high-resolution imagery, not a stretched Sentinel-2 thumbnail. Setting a product label does not convert or calibrate the raster.

Spatial grid and no-data

The raster reader windows the AOI, reprojects/resamples channels onto a shared grid, applies supported scale/offset metadata and retains validity masks. The analysis-grid value is the maximum longest-side pixel count, not a ground resolution in meters. Choosing 1024 px does not invent native detail or make an entire satellite scene run at full source resolution.

Start at 192 or 384 px; increase to 768 or 1024 only when needed. A larger AOI or more hyperspectral channels increases memory and time. If an all-band budget is exceeded, reduce the AOI or grid: anomaly processing does not silently discard spectral bands.

Hyperspectral inputs

RF, SVM, XGBoost and the trained U-Net can use mapped hyperspectral channels. Foundation and native pretrained heads have specific sensor/band requirements. The anomaly pipeline uses all connected science channels and reports excluded quality/display/atmospheric channels and constant channels. Check the saved band schema and source provenance rather than assuming every channel in an archive is a measured wavelength.

Use band coregistration for inter-band displacement. Sharing a CRS and pixel grid does not itself prove optical band alignment.

Inspect

Reports, classes & downloads

Find outputs, compare agreement, and export geospatial evidence.

  1. Open Mission workspace, choose the mission and select Data & results → Runs & results.
  2. Locate the run by job, time and state. Wait for completion, or expand errors for a failed model.
  3. Review model identity, input provenance, selected combination, band alignment, class legend and evaluation scope.
  4. Use the map/review action on the image output, or download its artifacts.

Read the map layers

  • Land-cover/consensus: the final class decision under the reported combination policy.
  • Individual model maps: what each successful worker predicted.
  • Disagreement: pixels where successful model predictions differ; orange highlights locations worth inspecting.
  • Agreement: pixels where the compared predictions match. This does not prove the class is correct.
  • Confidence: a model/combination score. It is not automatically a calibrated real-world probability or measured accuracy.
  • No-data: unavailable or invalid analysis pixels; they are not a land-cover class.

The class breakdown lists names, counts and area shares on the analysis grid. A class can be part of the taxonomy but absent from this AOI. With only one successful model, there is no independent multi-model agreement evidence even if the disagreement map is empty.

What to save

Download the full JSON report for provenance, model choices, metrics and errors; GeoTIFFs for GIS analysis; and PNG previews for quick visual comparison. Review-history and corrected products remain separate from the original predictions. Do not infer class IDs from display colors: consult the report taxonomy and raster metadata.

Outputs use the reported resampled analysis grid. They do not replace the full-resolution source files. Metrics are meaningful only for the reference scope named in the report; see Precision, Recall & F1.

Inspect votes & correct a result

See who predicted what and explicitly save your own classification.

  2. Click a valid analysis pixel, or enter its longitude/latitude in the inspector. The vote table lists each model's class, the original final class and your reviewed class where available.

What gets saved?

The saved review retains the source run, job/image scope, geometry and approved class. Reviewed products and reference records are stored locally while original model predictions remain intact. Saved references feed readiness checks; an algorithm is relevant only where its own prediction conflicts with the approved class.

Keep independent validation regions separate from fitting data. Overlapping later decisions own the affected pixels; repeatedly drawing the same correction does not multiply unique evidence. Check the source date and land-cover definition before overriding the map.

For more precise object boundaries, use SAM segmentation proposals in the same inspector. A proposal is not ground truth until you assign a class and explicitly save it.

Inspect

SAM object segmentation

Prompt candidate boundaries, compare masks and approve a labeled region.

SAM 3 Tracker proposes object boundaries. It does not identify land-cover classes, vote in the LULC ensemble or train automatically in the current app.

To segment a source image before classification, choose the released SAM model in Manual inference and use Draw SAM prompts on chosen image. To segment during review, follow these steps.

  1. Open a completed classification result in the image comparison viewer. Locate SAM 3 interactive segmentation in the inspector.
  2. Check Display bands, normally RED,GREEN,BLUE. These must exist in the connected raster. This is a three-band display composite; other spectral channels remain available to classifiers.
  3. Click inside the target object and choose Include clicked point. Add exclude points to reject neighboring regions if needed, then choose Segment points. At most 32 prompt points are accepted.
  4. Alternatively choose Draw image region, select a rectangle and choose Segment selected region. A polygon supplies its enclosing box, not an already accepted final boundary.
  5. Watch segmentation progress. Compare the proposed masks and previews; use Preview on map or download GeoTIFF/GeoJSON.
  6. Choose Use this boundary, assign a semantic class in the review form, set its reference role and choose Save my classification.

Quality shown on a proposal is the model's own mask estimate, not independently measured Precision, Recall or F1. History retains prompts, display bands, geometry, model provenance and candidate outputs. Unapproved masks never become references.

The source window is read on a bounded, georeferenced grid, up to 1024 pixels on the longest side. Inspect thin or small features at that resolution. SAM fine-tuning is unsupported until a supervised mask-training adapter exists; approved masks can instead support the semantic classifier correction workflow.

Detect anomalies

Full-spectrum anomaly detection

Run four detectors, adjust sensitivity and label unusual spectra.

Choose imagery and detectors

Open a mission's Spectral anomalies tab. Select a job and images with ready raster access. Choose Regularized RX, Local RX, Isolation Forest and/or Spectral autoencoder. They use all connected science bands; exclusions and constant channels are reported explicitly.

DetectorWhat it compares

  2. Set a grid and percentile; the initial percentile is 99.5. Choose a minimum vote count no greater than the number of enabled detectors.

Understand sensitivity

A percentile of 99.5 selects approximately the top 0.5% of scores per detector, subject to ties. A lower percentile flags more pixels; a higher one flags fewer. Requiring more votes is generally more selective. Percentiles are scene-relative ranks, not probabilities. High scores can indicate real targets, clouds, shadows, bad calibration or sensor artifacts.

Review and adapt

Inspect individual heatmaps and combined votes. Change percentile or minimum votes and choose Apply threshold · save new view; this saves another threshold interpretation of existing scores rather than retraining detectors. Choose Inspect & review on map, select a pixel or drawn AOI, label it Confirmed anomaly or Normal background / false alarm, choose confidence and reference role, then save.

Approved normal training pixels can support a separate reviewed-background candidate; confirmed anomalies and validation references are excluded from background fitting. Benchmark validation/test images are protected. Autoencoder reconstruction holdout loss is not anomaly accuracy. Precision/Recall/F1 require human validation references and carry their sampling limitations.

Reference quality

Use surveyed or independently interpreted labels where possible. Label homogeneous regions and avoid uncertain boundaries, cloud contamination and outdated land use. A confidently entered class can still be wrong; confidence is your assessment, not a model score.

Keep validation samples spatially and, preferably, temporally independent. A label used for fitting cannot also provide independent proof of accuracy. Point references provide little pixel support on coarse grids; check counts and support in the report.

Be deliberate about uncertain training labels

Semantic fitting requires confidence of at least 3/5. Use independent evidence to choose the validation role. A training confidence score describes your review, not measured accuracy.

Import polygon shapefiles

Read external polygons, check projection and map attributes to class labels.

Prepare the files

Use a ZIP containing matching .shp, .shx and .dbf components, ideally with .prj and optional .cpg. You can also select the matching components together. The importer expects polygon geometry, not arbitrary vector formats or an unlabeled raster.

  1. Open Data & results → Label data → Import polygon shapefile and choose the target job.
  2. Select the files. If projection is missing, enter the actual source CRS, such as EPSG:32636, in Source CRS override. Do not guess EPSG:4326 for projected coordinates.
  3. Choose text encoding if automatic interpretation is wrong, then Read polygons & attributes. If a ZIP has multiple datasets, choose one and read again.
  4. Check polygon count, invalid-feature messages and the coordinate transformation. Use Preview polygons on map to verify location.
  5. Select a Class attribute and map each value to the class name you want, or enter One class for all polygons.
  6. Choose Image scope, reference role, confidence and a source note. Explicitly choose whether to skip unlabeled polygons.
  7. Choose Import references into job. Inspect the imported/skipped summary.

Reading and previewing do not approve ground truth. The import/commit step saves your explicit class mapping and role. Original source files, checksums, attributes and normalized WGS84 geometries are retained for provenance. Imported training references participate in the saved correction policy; validation references are excluded from fitting.

Limits and common problems

The importer limits uploads to 20 components and 64 MiB combined input, ZIPs to 1,000 entries and 256 MiB declared expanded data, and datasets to 10,000 polygons and 2 million vertices. The class-mapping UI supports up to 200 distinct values for the selected field. Choose a categorical class field instead of a unique polygon ID. Split large datasets or simplify excessive geometry before import.

Missing components, duplicate components, wrong encoding, invalid geometry or an incorrect CRS must be resolved at the source. Keep class definitions compatible with the job or pretrained model you intend to train.

Use Check sample coverage to check each class, then choose Train a candidate or the model’s fine-tuning action. Review progress, validation and errors in the same workspace.

RF/SVM/XGBoost refit; U-Net can continue a compatible checkpoint; Prithvi trains a downstream head with its foundation encoder frozen; the ensemble refits compatible members; native pretrained heads require their own compatible data/taxonomy for fine-tuning. SAM training is not implemented. The anomaly models use reviewed-background refits rather than semantic class training.

The saved automatic policy

The approved default is 20 distinct relevant reviewed regions, 500 unique corrected analysis pixels and 2 images per relevant algorithm, with confidence at least 3/5. The displayed persisted policy is authoritative; saved settings survive restarts. Thresholds apply per algorithm, not to all mission annotations pooled indiscriminately.

  • A correction is relevant where that algorithm's saved prediction differs from your approved answer.
  • Overlapping edits are deduplicated; the latest decision owns each pixel.
  • Validation/test references and held-out pixels do not count as fitting evidence.
  • Each eligible algorithm gets its own separate, versioned candidate run.
  • Evidence is reserved to prevent duplicate/concurrent batches, and consumed only after successful completion.
  • Failures remain inspectable; the same failed batch is not automatically repeated without new evidence.

The app checks readiness after saved corrections and related state changes, and at service startup. It announces when automatic training starts; no additional confirmation is requested. The backend must be running. Counts below the saved thresholds are a normal waiting state, not a failed training job.

New versions do not silently replace established models

Keep the original prediction and report, inspect the candidate's training provenance and independent metrics, and compare the same reference scope. Candidates can seed later compatible training. Ordinary inference does not automatically adopt a training candidate. Review the independent metrics and use Qualify & move to inference when the rule is met. Use the model’s return-to-training action when you need to revise it. Operational pipelines require a qualified version.

Reference roles and the minimum confidence are described under reference quality. Add accurate training labels rather than trying to satisfy counts with repeated or uncertain edits.

The standalone tool decodes the full stack and can be expensive; use manageable files or prepare a smaller source externally. Keep the original raster and verify borders/validity after shifts.

Precision, Recall, F1 & evaluation

Interpret scores, class support and validation scope without confusing agreement with accuracy.

MeasureQuestion answered
PrecisionOf the pixels predicted as a class, how many match the reference? TP / (TP + FP).
RecallOf the reference pixels belonging to a class, how many were found? TP / (TP + FN).
F1The harmonic mean of Precision and Recall; useful when both false positives and missed detections matter.
Macro averageGives each evaluated class equal weight. Read per-class scores and support alongside it.
AccuracyFraction of evaluated reference pixels classified correctly. A dominant class can hide weak minority classes.
IoUClass overlap: intersection divided by union. Mean IoU summarizes class overlap.
SupportHow much reference evidence contributed to a class score.

Always read the scope

Explicit validation geometries are excluded from training. When explicit validation is absent, trained workflows can use an internal eastern spatial holdout with a buffer; the report identifies this. That is weaker evidence than independent scenes or dates. A model chosen using validation should be assessed separately on untouched test data.

A blank or unmeasured metric means the required reference support is unavailable. It does not mean zero performance or perfect performance. Per-class values with little support can be unstable. Human-review sampling often overrepresents difficult pixels; anomaly-review metrics need that selection-bias caveat.

Agreement is not validation

Several models can share the same bias. Detector vote counts, anomaly percentiles, confidence values and SAM mask quality are not measured accuracy. Evaluate against independent references. For anomalies, normal and anomaly references are a different taxonomy from semantic LULC classes.

Benchmark reports

Existing benchmark missions, if present, appear in Mission workspace → Data & results → Runs & results. Read the dataset, region, class crosswalk, spatial grid, train/validation/test split and sampling protocol. A regional pilot or binary water test is not a global multiclass leaderboard result. Frozen inputs and original references are retained for reuse; official validation/test imagery must not enter fitting.

Spatial alignment. This app's alignment tools correct band translations within an image.
Inference
Applying a fitted model to produce predictions. Some job workflows fit a model before predicting.
Reference / ground truth
A human-approved label with geometry, scope and provenance. It can still be mistaken; automatic predictions are not ground truth.
Validation / test
References held out from fitting; validation can guide model selection, while untouched test data assesses the fixed selection.
Checkpoint / candidate
A saved model state / a new separately versioned training outcome.
Consensus / disagreement
A combination of predictions / where compared predictions differ. Neither is independent truth.
Percentile / vote
A score rank / a detector decision count. Neither is a calibrated probability.

Current product boundaries

  • Catalog and preview access are separate from science-raster analysis.
  • Local imagery imports connect to mission/job creation. Only installed adapters and supported vector formats can be used. Operational promotion requires a supported model and its qualification evidence.
  • Archived hyperspectral bundles are not automatically unpacked into calibrated stacks.
  • Native pretrained heads require their released sensor/product/band/taxonomy contracts and run separately.
  • Prithvi's original foundation worker freezes the encoder; SAM fine-tuning is unsupported.
  • Band alignment does not perform multi-scene or multi-date registration.
  • Review outputs are bounded-grid analyses, not guaranteed full-scene native-resolution products.
  • Automatic learning needs the backend running and sufficient new relevant evidence. Training references below confidence 3/5 are excluded by the job worker.
  • Metrics require the documented reference scope. Benchmark pilots and agreement figures are not proof of global accuracy.
  • Persistence is local; backups and deployment access controls remain operator responsibilities.
